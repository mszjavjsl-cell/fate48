# 8saju 미러 서비스 분석 및 만세력 계산 규칙 대조

작성일: 2026-10-07  
대상: `https://8saju.com/mobile/`, `https://8saju.com/desktop/`  
목적: 승인받은 미러 서비스의 화면 구조를 참고하되, 계산 엔진은 우리 규칙과 분리하여 검증한다.

## 1. 결론

8saju의 화면 골격은 미러 서비스의 출발점으로 사용할 수 있다. 다만 색상만 바꾸는 수준의 복제는 피하고, 정보 구조는 유지하면서 입력 방식, 계산 근거 표시, 반응형 레이아웃, 접근성을 개선한다.

계산 엔진은 그대로 이식하지 않는다. 확인된 8saju 계산 방식은 다음과 같다.

- 연주와 월주는 절입 **분 단위**에서 동시에 바뀐다.
- 출생지나 시간대를 입력받지 않고 한국 사용을 전제로 한다.
- 일주와 시주 경계에 서울 기준으로 보이는 **고정 30분 보정**을 적용한다.
- 기본 자시는 `23:30–01:29`로 처리한다.
- 23:30 이후에는 조자시/야자시 전환을 제공한다.
- 대운 방향은 년간 음양과 성별을 조합하는 일반 순역 규칙과 일치한다.
- 첫 대운은 정밀 교운시점이 아니라 `절입차 ÷ 3일`을 반올림한 정수 대운수로 표시한다.
- 반올림 결과가 0이면 1로 올리므로 화면의 첫 대운수는 1–10 범위다.
- 현재 대운 강조는 `현재연도 - 출생연도 + 1`의 연 나이를 사용한다.

우리 엔진은 표준시·시간대·절입 instant·정밀 교운일을 보존한다. 따라서 8saju 결과는 호환 표시와 회귀 비교에 사용하고, 제품의 계산 진실 공급원(source of truth)으로 사용하지 않는다.

## 2. 미러 범위와 디자인 원칙

### 유지할 구조

- 상단 네 기둥: 연주·월주·일주·시주
- 원국 아래 대운·세운 흐름
- 대운의 10년 단위 가로 탐색
- 대운수(나이)와 대응 양력 연도를 한 화면에서 함께 읽는 이중 시간축
- 선택한 대운 아래에 10개 세운을 같은 열 기준으로 배치하는 연동 구조
- 양력·음력·윤달, 성별, 생년월일시 입력
- 최근 명조와 저장 명조로 빠르게 다시 열기
- 조자시/야자시처럼 결과에 영향을 주는 계산 옵션

### 변경할 표현

- 8saju의 색상, 아이콘, 서체, 카드 모양, 여백, 애니메이션은 그대로 복제하지 않는다.
- 첫 화면은 원국과 현재 흐름만 보여주고, 십신·십이운성·합충형파해·신살은 접어서 연다.
- 모바일에서는 가로표 전체를 축소하지 않고, 고정 라벨과 가로 스크롤 조합을 사용한다.
- 입력 화면에 출생지, IANA 시간대, 표준시/진태양시, 자시 정책을 명시한다.
- 결과 상단에 `계산 기준 보기`를 두어 절입시각, 보정값, 순역, 첫 교운 계산을 펼쳐 본다.
- 대운수 `8`과 정밀 교운일 `1997-04-17 11:43`을 동시에 보여준다.
- 외부 서비스 호환 결과와 우리 정밀 결과가 다르면 어느 쪽이 오류인지 단정하지 않고 적용 규칙을 나란히 표시한다.

### 권장 화면 방향

`8saju의 압축된 원국/대운 구조 + 우리 앱의 계산 투명성 + 기존 디자인 조사에서 도출한 카드 계층`으로 정리한다.

특히 대운·세운 영역은 8saju의 장점을 적극적으로 유지한다. 사용자가 별도로 출생연도와 대운수를 더하지 않아도 되도록 각 대운 열에 `대운 시작 나이`와 `대응 연도`를 동시에 표시한다. 대운을 선택하면 그 10년의 세운이 바로 아래에서 같은 시간축으로 정렬되어야 한다.

```text
대운 나이     8세          18세          28세
시작 연도     1997         2007          2017
대운          庚午         辛未          壬申

선택 대운     8세 · 1997–2006 · 庚午
세운 연도     1997  1998  1999  ...  2006
당시 나이      8세   9세  10세  ...  17세
세운          丁丑  戊寅  己卯  ...  丙戌
```

이 영역에서 변경할 것은 정보 관계가 아니라 시각 표현이다. 색상, 글꼴, 카드 형태, 선택 강조, 스크롤 동작은 우리 디자인 시스템으로 바꾸되 `나이 ↔ 연도 ↔ 대운 ↔ 세운`의 즉시 대응 관계는 훼손하지 않는다.

모바일 기본 순서는 다음과 같다.

1. 인물·출생정보 요약
2. 사주 원국 4주
3. 현재 대운·세운 요약
4. 대운 타임라인
5. 세운·월운 탐색
6. 합충형파해·신살·오행 상세
7. 계산 기준과 중간값

## 3. 확인한 8saju 계산 규칙

### 3.1 절입과 연·월주

- 12절의 시각을 `YYYY/MM/DD HH:mm:00` 형식으로 보관한다.
- 비교는 이전 절입 이상, 다음 절입 미만의 반개구간이다.
- 입춘 정확한 분부터 연주와 월주가 새 값으로 바뀐다.
- 초 데이터는 없으므로 같은 분 안의 초 경계를 구분하지 못한다.

2000년 입춘 관측:

| 입력 | 8saju 연주 | 8saju 월주 | 내부 입춘 |
|---|---|---|---|
| 2000-02-04 03:27 | 己卯 | 丁丑 | 다음 절 `2000-02-04 03:28` |
| 2000-02-04 03:28 | 庚辰 | 戊寅 | 이전 절 `2000-02-04 03:28` |

### 3.2 일주와 시주 경계

소스와 합성 사례를 함께 확인한 결과, 일수 계산에는 다음 형태의 식이 사용된다.

```text
dayCount = floor((date.valueOf() + 9.5 hours) / 24 hours)
```

한국 표준시가 UTC+9인 환경에서 이는 민간시 00:00이 아니라 **23:30 경계**가 된다. 시주 구간도 같은 30분 이동을 사용한다.

| 입력 | 일주 | 시주 |
|---|---|---|
| 2000-01-01 22:59 | 戊午 | 癸亥 |
| 2000-01-01 23:00 | 戊午 | 癸亥 |
| 2000-01-01 23:29 | 戊午 | 癸亥 |
| 2000-01-01 23:30 | 己未 | 甲子 |
| 2000-01-01 23:59 | 己未 | 甲子 |
| 2000-01-02 00:00 | 己未 | 甲子 |

23:45에서 조자시를 야자시로 전환하면 일주만 `己未 → 戊午`로 돌아가고 시주는 `甲子`로 유지됐다.

이는 우리 `kr-traditional-v1-draft`의 기본값인 민간시 00:00 일 경계, `23:00–00:59` 자시와 다르다. 호환이 필요하면 별도 프로필로 구현해야 한다.

예시 프로필 이름:

```text
kr-8saju-compat-v1
  fixedLongitudeCorrectionMinutes = -30
  dayBoundaryLocal = 23:30
  ziHourLocal = [23:30, 01:30)
  lateZiToggle = supported
```

`-30분`은 관측된 동작을 표현한 이름일 뿐이다. 8saju가 어떤 지점의 경도나 어떤 학파의 보정값을 의도했는지는 화면과 공개 코드만으로 확정할 수 없다.

### 3.3 대운 순역

일반적인 규칙과 일치한다.

| 년간·성별 | 방향 |
|---|---|
| 양년 남성 | 순행 |
| 음년 여성 | 순행 |
| 음년 남성 | 역행 |
| 양년 여성 | 역행 |

판정에는 입춘 경계를 반영한 화면 연간을 사용한다.

### 3.4 첫 대운수

8saju의 핵심 식은 다음과 같다.

```text
순행 rawAge = (nextTerm - birth) / 3 days
역행 rawAge = (birth - previousTerm) / 3 days
displayAge = floor(rawAge + 0.5)
if displayAge == 0: displayAge = 1
```

그 후 `displayAge`, `displayAge + 10`, `+20` 형식으로 10개 대운을 표시한다.

우리 방식과의 차이:

| 항목 | 8saju | 우리 기본 프로필 |
|---|---|---|
| 절입 정밀도 | 분 | 최소 초 |
| 기산 결과 | 반올림 정수 나이 | 년·월·일·시·분·초 |
| 0에 가까운 값 | 1세로 올림 | 실제 0에 가까운 기간 보존 |
| 첫 교운일 | 표시·보존하지 않음 | 현지 달력 덧셈으로 계산 |
| 이후 교운 | 정수 나이 10년 간격 | 첫 교운일에서 달력상 10년 간격 |
| 현재 대운 판정 | 연 나이 기준 | 실제 교운 instant 기준 |

### 3.5 절입 순간의 대운 정책

2000-02-04 03:28 입춘과 같은 분에 태어난 양년 여성은 역행으로 바뀌고, 이전 절을 방금 들어온 입춘으로 잡아 원시 시간차가 0에 가까워진다. 그러나 최소값 보정으로 첫 대운수는 1이 된다.

따라서 8saju 호환 프로필은 다음 정책을 가진 것으로 정리할 수 있다.

```text
term interval         = [currentTerm, nextTerm)
reverse basis at term = currentTerm
rounded minimum age   = 1
```

우리 기본 프로필의 `strict-adjacent-term` 미확정 항목과 충돌하므로, 이 경계는 반드시 별도 테스트로 잠가야 한다.

### 3.6 음력 입력

공개 클라이언트 코드에서 음력→양력 변환은 외부 Cloud Function 프록시를 통해 달력 API를 호출한다. 윤달 여부를 API 결과와 대조하고, 변환된 양력 생년월일로 명식을 계산한다.

우리 엔진은 외부 네트워크가 없어도 재현 가능한 버전 고정 음력 데이터셋을 우선한다. 외부 API를 사용하더라도 공급자·버전·응답 원문·캐시 정책을 감사 로그에 남겨야 한다.

## 4. 기존 골든 케이스와 절입 데이터 대조

아래 8saju 값은 사이트 내부의 `x01/x02` 표시를 읽은 것이다. 우리 값은 현재 `unlocked` 상태의 임시 fixture다.

| 사례 | 절기 | 8saju | 우리 fixture | 차이 |
|---|---|---|---|---:|
| GC-LUCK-001 | 망종 | 1989-06-06 02:04:00 KST | 1989-06-06 02:05:14 KST | -74초 |
| GC-LUCK-002 | 청명 | 1986-04-05 11:05:00 KST | 1986-04-05 11:06:07 KST | -67초 |
| GC-LUCK-003 | 대설 | 1975-12-08 02:45:00 KST | 1975-12-08 02:46:11 KST | -71초 |

세 사례 모두 8saju가 약 1분 일찍 잡힌다. 이것만으로 어느 값이 정답이라고 판정할 수는 없다. 권위 절입 데이터 공급원을 잠근 뒤 재검증해야 한다.

### GC-LUCK-001에 미치는 영향

1989-05-13 07:15 여성은 음년 여성이라 순행이다.

- 8saju 방식 표시: 첫 대운수 `8`, 이후 `18·28·38…`
- 우리 방식: `1997-04-17 11:43 KST` 정밀 교운
- 8saju 절입값을 우리 정밀 환산식에 넣은 가상 결과: `1997-04-17 09:15 KST`

마지막 값은 8saju가 실제로 제공하는 교운일이 아니다. **절입 데이터만 8saju 것을 사용하고 우리 환산식을 적용했을 때의 영향 분석**이다.

### GC-LUCK-002에 미치는 영향

- 8saju 방식 표시: 첫 대운수 `1`
- 우리 방식: `1987-03-11 01:39 KST`
- 8saju 절입값을 우리 정밀 환산식에 넣은 가상 결과: `1987-03-10 23:25 KST`

### GC-LUCK-003에 미치는 영향

- 8saju 방식 표시: 첫 대운수 `9`
- 우리 방식: `1985-03-20 21:38 KST`
- 8saju 절입값을 우리 정밀 환산식에 넣은 가상 결과: `1985-03-21 00:00 KST`

## 5. 구현 방침

### 엔진

1. `kr-traditional-v1`을 제품 기본값으로 유지한다.
2. 8saju 호환 동작은 `kr-8saju-compat-v1` 프로필로 분리한다.
3. 프로필이 공유하는 부분은 간지, 십신, 십이운성, 대운 간지 진행뿐이다.
4. 절입 데이터, 시각 보정, 일 경계, 자시 정책, 대운 기산은 프로필별 전략 객체로 분리한다.
5. 화면 호환을 위해 `roundedLuckAge`를 파생값으로 제공하되 `firstTransitionInstant`를 버리지 않는다.

권장 결과 형태:

```json
{
  "luckCycle": {
    "direction": "forward",
    "roundedLuckAge": 8,
    "firstTransitionLocal": "1997-04-17T11:43:00+09:00",
    "referenceComparisons": [
      {
        "profileId": "kr-8saju-compat-v1",
        "roundedLuckAge": 8,
        "firstTransitionLocal": null
      }
    ]
  }
}
```

### 화면

- 기본 화면에는 정수 대운수를 큰 숫자로 보여 주되, 그 아래 정확한 교운일을 표시한다.
- `8세 전후` 같은 표현과 `1997-04-17 11:43`을 같은 값처럼 섞지 않는다.
- 대운 카드에는 시작 나이와 시작 연도를 함께 표시한다.
- 선택된 대운의 세운표에는 각 열마다 해당 연도와 당시 나이를 함께 표시한다.
- 대운과 세운의 열 중심선을 맞춰 상하 관계가 즉시 보이게 한다.
- 모바일에서는 현재 또는 선택 대운을 처음부터 화면 중앙에 두고 좌우로 탐색한다.
- 계산 상세에는 적용 프로필과 보정값을 배지로 표시한다.
- 23시대 입력에는 자시 정책이 결과를 바꿀 수 있다는 안내를 즉시 노출한다.
- 출생지 미입력 시에는 `서울 기준 고정 보정` 같은 명시적 기본값을 보여준다.

## 6. 검증 우선순위

1. 권위 절입 데이터 공급원을 확정하고 세 골든 케이스를 다시 잠근다.
2. 23:29:59 / 23:30:00 / 23:59:59 / 00:00:00 경계 사례를 추가한다.
3. 절입 1초 전 / 정확히 동일 / 1초 후의 연주·월주·대운 기준 절을 추가한다.
4. 순행·역행 네 조합을 같은 생년월일로 교차 검증한다.
5. 대운 원시값이 0.49, 0.50, 0.51년 및 9.49, 9.50, 9.51년인 반올림 경계를 검증한다.
6. 한국 역사 표준시와 해외 시간대가 일주·시주·절입 표시에 미치는 영향을 검증한다.
7. 음력 평달·윤달·연말 변환을 오프라인 데이터와 외부 API로 교차 검증한다.

## 7. 증거와 제한

- 사이트 화면의 합성 입력 결과와 공개 클라이언트 계산식을 함께 확인했다.
- 실제 사용자의 이름이나 생년월일은 입력하지 않았다. 경계 검증에는 합성 사례만 사용했다.
